01 / One Kind of Thing

The system is written in the same language as its work.

A service, a check, an AI agent — each is the same kind of object: a declared entity in one build graph, shipped by one command. The workers that build the system aren't bolted on from outside; they're described in the very language the system is built from. Adding a capability, a rule, or a whole new kind of worker is the same motion as adding a line of code — so there's nothing to integrate, because there's only ever one kind of thing.

everything is an entity
# a running service
bedrock_service(
    name          = "integrator",
    service_label = "com.bedrock.integrator",
    program       = ":main",
)

# an agent that writes code — declared like the service
agent_spec(
    name    = "implementer",
    prompts = ["//agents/prompts:implementer"],
    harness = "codex",
)
one command — humans + agents alike
$ repo publish -m "ship it"
02 / Rules as Reflexes

A standard is just an agent wired to an event.

Governance isn't a document people promise to follow — it's an orchestrating agent declared to wake on a class of events. The wiring is the rule: it names who reacts, and to what. Raising the bar means adding one of these entities, not standing up a new system — so every standard you care about becomes a reflex the environment can't skip.

  • a reviewer on a code pattern — every Python change gets a Fable security audit
  • a presubmit agent on every proposed change — it must pass before anything merges
  • background agents on idle capacity — improvement work that never blocks the queue
  • a meta-process on the trace archive — the system reading itself (§04)
the audit is an agent on an event
# DEFINE the agent — a security auditor on Fable 5
agent_spec(
    name    = "fable-auditor",
    prompts = ["//agents/prompts:security-review"],
    model   = "claude-fable-5",
    effort  = "high",
)

# WIRE it to an event — audit every Python change
agent_trigger(
    name    = "security-audit",
    agent   = ":fable-auditor",    # ← rule meets agent
    pattern = "**/*.py",           # matched at run time
    on      = ["added", "modified"],
)
03 / The Loop

It builds, reviews, and ships itself.

A generator agent writes the change — code, a service, even a new agent. Other agents review it and vote; nothing merges itself. Then it deploys, reshaping the running system — including the very process that produced the change. Every step is append-only and attributable, so the system is also, continuously, its own audit log.

04 / The Mirror

Lived friction becomes filed work.

The same machinery turns inward. A layer of meta-processes reads the agents' own execution traces — not what they were told to do, but what actually happened — and converts recurring trouble into filed work. The system doesn't just do the work; it studies how the work goes and improves how it improves.
